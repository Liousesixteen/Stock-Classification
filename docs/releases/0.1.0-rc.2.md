# 0.1.0-rc.2 发布候选说明

发布日期：2026-07-27

## 版本目标

本候选版本集中修复首次使用、数据可信边界、自动任务噪音、失败恢复和窄屏可用性问题，使四工作区闭环能够在空库、示例库和真实研究数据之间保持一致且不误导。

## 主要改进

- 初始化默认改为空库；示例数据必须显式启用，并采用只插入、不覆盖用户资料的安全策略。
- 研究工作台只展示数据库中的真实活跃公司、成果、证据和任务；示例公司明确标注且不计入研究进度。
- 行情条明确标注为非实时演示数据，不再暗示外部行情源正常。
- 证据统一按“已核验”或“具备可追溯 HTTP(S) 原文链接且未过期、未驳回”判定；AI、档案评分、图谱、成果库和导出共用同一规则。
- 自动任务仅围绕已关注、已建档、已同步、已有研究或证据的活跃公司生成；读取任务列表不再隐式修改数据库。
- Provider 默认关闭，必须通过环境变量显式启用；未知 Provider 配置直接报错，避免意外访问未授权数据源。
- 数据源刷新失败会保留最近一次仍在有效期内的成功缓存，同时展示最新失败状态和原因。
- 成果完整度取消无证据基线；无可追溯引用的报告与 AI 结论保持“待完善”。
- 公司档案加载具备明确的加载、失败和原地重试状态。
- 修复窄屏工作台重叠、任务列表横向溢出，并补充侧栏键盘调整、读屏标签和工作区语义结构。
- standalone 发布包会拒绝 SQLite、WAL/SHM 和备份目录；Docker 运行镜像包含备份、恢复与运维检查脚本。

## 上线前外部门禁

1. 吊销所有曾暴露的模型 API Key，并在受控密钥管理中创建新 Key。
2. 完成各数据源的书面商用授权与展示边界确认后，再显式启用对应 Provider。
3. 在目标部署机完成 Docker 构建、TLS 反向代理、持久卷、定时备份和隔离恢复演练。
4. 使用 20–50 家跨行业样本运行真实 Provider 验收，记录字段覆盖率、延迟和失败率。
